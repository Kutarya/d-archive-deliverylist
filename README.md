# Invoice Atelier

Android: **1.5.2**. Windows: **1.4.1**.

Android 1.5.2 fixes four retry failures after an archive write is rejected: fixed document settings, archived document edits, document approval and reading again. Failed explicit saves restore the affected records while preserving newer work, leave corrections available for retry and report the error. The photo queue, one-sheet Excel export and fixed document settings are retained. Existing archives, source photos and signing keys are preserved. See [Android 1.5.2 release notes](release/RELEASE-1.5.2.md), the [development log](GELISTIRME_NOTLARI.md) and this version's evidence in `artifacts/1.5.2/`. Windows 1.4.1 has not been repackaged with these changes.

An offline document archive for Windows, Android phones and tablets. Read invoice and delivery-note photos, review the extracted details and export Excel files with live formulas, PDFs and images.

## Get started

1. On Windows, open `release/windows/Invoice-Atelier-1.4.1.exe`. No installation is needed. On Android, install `release/android/Invoice-Atelier-1.5.2.apk` over the existing application.
2. On Android, select **Take a photo**, **Choose from gallery** or **Choose files**. On Windows, use **Take a photo** or **Upload photos**. Choose **Enter manually** to create a document without a photo. Select up to 20 JPG, PNG, WebP or PDF files at a time. PDFs can contain up to 20 pages; each page becomes a separate document. If camera permission is denied, the app explains how to allow access and opens the app's Android settings on request; gallery selection remains available without camera permission.
3. Compare the photo with the extracted details. Review the document number, date, companies, items, quantities, prices, discount, VAT and currency. Complete any missing fields. Photos can be enlarged, rotated and read again. **Replace photo** keeps your entered details and records the previous photo so it can be restored. Reading runs in the background: add another file or switch documents while it works. Stop a slow read to enter the details manually.
4. Select **Confirm details**, then choose a new Excel file or an existing archive. Save several documents together, save each one separately, or save only the current document. **All ready documents** lets you archive completed work while incomplete documents remain in review. Invalid fields show their errors next to the input.
5. Open an archived file and use the **Excel**, **PDF** and **Image** tabs to preview or download it. Use **Edit documents** or **Edit rows** to correct archived information; saving updates the Excel, PDF and image exports. **Rename file** changes the archive name. Source photos and previous photo versions are kept with the records.

## Updating from 1.0.0

This release keeps the same application ID, Windows archive location, Android signing key and archive schema. Existing names, company details, item descriptions and photos are preserved. The interface and generated output languages can be selected independently.

On Windows, close the old application before opening the new EXE. On Android, install the new APK over the existing application. Export a backup before uninstalling the app.

Android's Back button closes an enlarged photo before its document editor, cancels open confirmation dialogs, and returns from an open file to the archive. At the upload home page, Back places the app in the background. Cancelling the Android camera returns quietly without adding an empty document.

If Android terminates the WebView renderer, the app handles the termination and recreates the screen. A pending native export returns to the same document view. When a native window is open, recreation waits until its activity result is delivered so the prepared file can finish writing.

Excel files generated by the legacy Turkish 1.0.0 edition, the English 1.0.1 edition and all three languages in 1.3.0–1.4.3 can be reimported. Single-sheet 1.5.0 exports can also be edited and reimported. Edited quantities, prices, discounts, VAT and document fields are applied to matching records. Hidden item IDs travel with sorted table rows. New rows inside an item table receive IDs on import. Invalid inputs or damaged field bindings are rejected before they replace archive records. Invoices added after an earlier export are preserved when that file is reimported.

## Language settings

Open **Settings** from the sidebar or bottom navigation. Choose **English**, **Čeština** or **Türkçe** separately for:

- **Interface language**: navigation, settings, fields, buttons, statuses, validation errors and application dialogs.
- **Output language**: generated Excel worksheet names, headings, document types and units; PDF and generated image labels; generated filename prefixes and localized dates and amounts.

Both settings default to English and are saved on the device. **Use interface language for outputs** copies the current interface choice to the output setting. A different output language is supported: for example, a Czech interface can produce Turkish Excel files and PDFs.

Language changes preserve source photos, names, identifiers and entered document content. External workbooks and original downloads retain their original content. Backup import keeps the current device's language preferences. Operating-system file pickers and camera applications follow their own device language settings.

## Fixed document details

On Android 1.5.2, open **Settings → Fixed document details** to save supplier and customer names, tax IDs, addresses, transport, vehicle registration, delivered/received names, notes and a fallback currency. Save the form to keep it on this device. Disable **Use these details for new documents** to stop applying it. If saving fails, your edits remain in the form and you can retry.

New manual documents receive these defaults. New photo readings use them only for missing fields; a currency actually read from the photo takes priority. Tax IDs and addresses are filled only when the source company matches the configured company, or the company field is empty. Changing defaults does not rewrite pending or archived documents. **Fill empty fields in pending documents** is an explicit action that preserves populated fields and skips documents currently being read. These settings work offline. No Firebase service or admin panel is required or deployed.

## Excel calculations

- Android 1.5.2 creates exactly one worksheet, **Documents**, localized to the selected output language. The currency summary and every document appear on this same sheet. Supplier, customer, tax, address, order, delivery, notes and source filename fields remain present.
- Blue cells are editable. Gross = `ROUND(Quantity*UnitPrice,2)`. Discount = `ROUND(Gross*DiscountRate,2)`. Net = `ROUND(Gross-Discount,2)`. VAT = `ROUND(Net*VATRate,2)`. Total = `ROUND(Net+VAT,2)`. Per-document totals and the difference from a supplied source total recalculate on this sheet.
- `COUNTIFS` and `SUMIFS` summarize each supported currency separately. Changing a document currency moves its calculated amounts to that currency's summary row.
- Document and item IDs and original source data are in hidden columns on the same worksheet. There is no extra metadata worksheet. The print area excludes all hidden data and fits to one page in width and height. Large archives remain complete but are scaled down when printed; use the worksheet on screen for readable detail.
- Add new invoices through the app and export again to extend the document layout. Existing downloaded files are unchanged; download a fresh export to obtain the single-sheet layout. The older Windows 1.4.1 package still generates its original multi-sheet format.
- Unspecified discount and VAT rates use the 0% values shown on the review screen. The app does not invent cost, profit or missing document values.

## Archive and device transfer

Approved documents and pending drafts are kept when the application restarts. Normal Windows close waits for the final save, including the last input. A storage error keeps the window open and displays the error so the save can be retried. Pending details are also saved when the app goes into the background. Uploading the same source photo does not add it twice. Pending reads resume when the application reopens. A damaged image does not stop the remaining files.

Android can recover a valid legacy `.bak` archive even when an interrupted write left no main file. A corrupt main file with a valid backup and an incomplete `.new` transaction are covered by native recovery checks.

**Backup and transfer** saves the archive, original and previous source photos, photo rotations and drafts to a JSON backup. Import that file on another device to merge it with the existing archive. Repeated imports skip duplicate documents. Devices do not synchronize automatically.

**Import Excel** restores files generated by this app. Workbooks from other applications are archived with their original bytes and sheets. Adding invoices to an external workbook preserves its original file and creates a separate formula-based export for the added invoices. External charts and analysis sheets are not rewritten.

Previews show merged headings and localized numbers, percentages and dates for the first 250 rows and up to 30 columns per visible sheet. Downloads include all records. Formulas without cached results are shown as formulas in the preview and calculated by Excel when opened.

## Photo recognition

Version 1.4.1 preserves full company names and grouped prices such as `1.250,50`, recognizes separate discount and VAT columns, and tolerates common OCR confusions in quantity headings. Completed totals determine currency ahead of a preprinted form heading. Czech whole-amount notation such as `600,-` is supported, impossible calendar dates are rejected, and date-shaped identifiers do not become issue dates. **Read again** asks before replacing fields, including manual corrections; cancelling leaves them intact.

Windows bundles Turkish, Czech and English Tesseract models. Android uses the bundled ML Kit Latin model. Reading photos does not require a cloud account or API key, and photos are not sent to an OCR server.

Clear printed documents work best. Handwriting, faint print, glare and skewed photos can cause recognition errors, so the review step is required. Blank forms do not produce invented document numbers or items. PDFs and PNGs are generated from approved records. Printed synthetic fixtures are tested separately from handwritten photos; some handwritten characters can still require manual correction. Use PDF for long documents that exceed the image export limit.

## Build from source

Node.js 22+, Android SDK 36 and JDK 21 are required. Android Studio's bundled `jbr` directory is available on this machine.

```powershell
npm ci
npm run assets
npm test
npm run pack:win
npx cap sync android
$env:JAVA_HOME='C:\Program Files\Android\Android Studio\jbr'
.\android\gradlew.bat -p android assembleRelease
Copy-Item android/app/build/outputs/apk/release/app-release.apk release/android/Invoice-Atelier-1.5.2.apk
```

Set the SDK directory in `android/local.properties`. Keep `android/signing.properties` and `android/fatura-atolyesi-release.jks` private and preserve them for future updates. Do not include them in a public source archive.

The Windows package uses its embedded files over `atolye://app`. It needs no Node.js installation or HTTP server. Android requires API 24 or later.
